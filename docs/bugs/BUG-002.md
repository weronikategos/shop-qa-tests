# BUG-002: The server accepts an invalid email address at sign-up

| Field | Value |
|---|---|
| Severity | **medium** |
| Status | open |
| Environment | flask-sql-shop in Docker; request sent without a browser (Postman / requests) |
| Test case | TC-M-01 |
| Automated test | `tests/test_known_bugs.py::test_server_rejects_invalid_email` |

## Steps to reproduce
1. Send `POST /register` with the fields `name=Test`, `email=ala@`, `password=test-password-1` (e.g. in Postman, body type `x-www-form-urlencoded`).

## Expected result
The server rejects the address and shows "Enter your name, a valid email and a password (at least 8 characters)."

## Actual result
The account is created (302 redirect to the login page). The same happens for `@example.com`, `ala@@example.com` and even a lone `@`.

## Why the browser doesn't show it
The field has `type="email"`, so the browser blocks such an address. That is only client-side validation, which is easy to bypass.

## Cause (from reading the code)
`shop/routes.py`, function `register`: the condition only checks `"@" not in email`.

## Suggested fix
Validate the address with a regular expression such as `^[^@\s]+@[^@\s]+\.[^@\s]+$`, or with the `email-validator` library.
